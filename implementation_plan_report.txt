2. CHANGES MADE
========================================================

[1] backend/.env.example
    - Added missing `GEMINI_API_KEY=` entry.
    - Problem: plan requires GEMINI_API_KEY (gemini_service.py reads
      settings.GEMINI_API_KEY) but it was undocumented.

[2] backend/requirements.txt
    - Added `pandas` and `numpy`.
    - Problem: plan section 1 lists pandas/numpy as required but they
      were missing from backend requirements (only in root requirements).

[3] frontend/src/lib/profile-store.ts  (line 42)
    - Fixed type: `title: str` -> `title: string`.
    - Problem: `str` is not a TypeScript type. This broke `tsc` and the
      production build (RoadmapWeek type).

[4] frontend/src/routes/index.tsx  (line 31)
    - `import.meta.env.VITE_API_URL` -> `import.meta.env["VITE_API_URL"]`
    - Problem: TS4111. tsconfig enables noPropertyAccessFromIndexSignature,
      so VITE_API_URL (from vite/client index-signature) must be accessed
      with bracket notation.

[5] frontend/src/routes/analysis.tsx
    - (a) Same env access fix as [4].
    - (b) `<Button size="xs">` -> `size="sm"`.
    - Problem: Button component only supports "icon" | "default" | "sm" |
      "lg" -> TS2322 type error.

[6] frontend/src/lib/auth-store.ts  (line 11)
    - Same env access fix as [4] (pre-existing error, trivial fix).

[7] frontend/src/routes/plan.tsx
    - Replaced `(step: any, c: any, p: any, item: any)` map params with
      proper types: RoadmapWeek / CourseItem / ProjectItem / CertItem /
      InterviewItem (derived from LearningPathData in profile-store).
    - Removed usage of non-existent fields (`c.platform`, `p.skills`).
    - Problem: @typescript-eslint/no-explicit-any errors; also the mock
      fallback data shape differed from backend schema (platform/skills
      vs provider/technologies).

[8] backend/test_ai_pipeline.py
    - Each test now uses a unique user id (`test_user_pipeline_<uuid>`).
    - Problem: tests reused the same user id, so the analyze endpoint's
      "fall back to latest uploaded resume" behavior leaked state between
      runs. Re-running the suite failed:
        test_03 (neither provided) got 200 instead of 400
        test_04 (portfolio only) reported source.resume == true
      Fixed by making tests idempotent.
